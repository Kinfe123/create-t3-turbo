# Self-Hosting Overview

create-t3-turbo runs as two separate surfaces in production: the Next.js application that serves both the web UI and the API, and the Expo app that communicates with that backend. Each surface has its own deployment path, and a few pieces of configuration must be updated before either works outside your local machine.

## Deploy the Next.js app to Vercel

Vercel is the path of least resistance for a Turborepo monorepo. The steps are:

1. Create a new project on Vercel and select `apps/nextjs` as the root directory. Vercel's zero-config system handles the build pipeline automatically.
2. Add your `POSTGRES_URL` environment variable so the Drizzle client can reach your database.
3. Assign your domain. The Expo app will need this URL to reach the backend when it is not running in development.

The `@acme/api` package must remain a **production** dependency only in the Next.js app. The Expo app and any other client apps should list it as a dev dependency only — this keeps backend code out of client bundles while preserving full type safety across the monorepo.

## Configure Better Auth for production

By default, Better Auth is configured for the development environment. Before deploying, you must update `trustedOrigins` in the `auth` package to include every origin that is permitted to make requests to the auth server. For the Expo app, add your Expo scheme to that list and update `auth/src/expo.ts` to match — the scheme defaults to `"expo"`.

Better Auth also ships with an Auth Proxy for OAuth providers in preview deployments. You do not need a separate server for this; the proxy is built in.

The following environment variables must be present in your production environment:

- `BETTER_AUTH_URL` — the public URL of your deployed Next.js app (e.g. `https://your-domain.com`).
- `AUTH_SECRET` — a random secret string. Generate one with `openssl rand -base64 32`.
- `AUTH_DISCORD_ID` and `AUTH_DISCORD_SECRET` — required if you are using the preconfigured Discord OAuth provider.
- `POSTGRES_URL` — the connection string for your Supabase (or other Postgres-compatible) database.

See [Environment Variables](/docs/configuration/environment) for the full variable reference.

## Push the database schema

Before the app can serve any authenticated requests, the Drizzle schema must be pushed to your production database:

```bash
pnpm db:push
```

This runs `turbo -F @acme/db push` and applies your schema to the database pointed to by `POSTGRES_URL`.

## Deploy the Expo app

Deploying an Expo app means submitting a production build to the Apple App Store or Google Play — not pushing to a server. Before building, update the `getBaseUrl` function in `apps/expo/src/utils/base-url.tsx` to return your backend's production URL instead of `localhost`.

Set up EAS Build to create the native bundle without a local native toolchain:

```bash
# Install the EAS CLI
pnpm add -g eas-cli

# Log in with your Expo account
eas login

# Configure your Expo app
cd apps/expo
eas build:configure
```

Then create a production build for your target platform:

```bash
eas build --platform ios --profile production
```

If you omit `--profile`, EAS uses the `production` profile by default. Repeat with `--platform android` for an Android build.
